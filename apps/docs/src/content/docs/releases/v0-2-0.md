**Data:** 2026-09-16 · tag `v0.2.0` · publicada no AWS CodeArtifact (Maven). Não saiu no npm.

É a primeira versão com tag. A publicação no Maven passou a sair só por tag: o `0.1.0-SNAPSHOT` que o CodeArtifact recebia a cada push na `main` ficou congelado no build de 2026-06-10. O código é o mesmo da `0.2.0-RC1` (tag `v0.2.0-RC1`); entre as duas, só mudam os números de versão.

## Pacotes

| Pacote                           | Maven                                         |
| -------------------------------- | --------------------------------------------- |
| `@singularidade/tokens`          | `digital.singularidade:tokens:0.2.0`          |
| `@singularidade/brand-assets`    | `digital.singularidade:brand-assets:0.2.0`    |
| `@singularidade/vaadin-bindings` | `digital.singularidade:vaadin-bindings:0.2.0` |

## `@singularidade/vaadin-bindings@0.2.0`

- Tema pai `singularidade-base`, que liga os `--lumo-*` aos tokens. Claro e escuro vêm do `tokens/defaults.css`, escrito à mão, com a Singularidade como marca padrão; os quatro `{marca}.{tema}.css` só ativam com `data-brand` e `data-theme` juntos.
- O bloco que reaplica as cores do escuro nos overlays passa da biblioteca `singularidade-ui-vaadin` para o tema pai.
- Vaadin 25: o pacote importa o BOM do Vaadin e declara o `flow-server` sem versão, então o app decide a versão do Vaadin; compila contra o 25.2.0. O `"lumoImports": []` saiu do `theme.json`.

## `@singularidade/tokens@0.2.0`

- Classes Java para e-mail, `digital.singularidade.tokens.email.EmailTokens{Integras,Singularidade}{Light,Dark}`, com os valores resolvidos por marca e tema.

## `@singularidade/brand-assets@0.2.0`

- 14 ícones Lucide a mais, usados pelo site integras.digital: de 71 para 85.
- Logos do Integras com margem uniforme de 5% e PNGs mais nítidos.
